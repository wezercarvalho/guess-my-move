# Licenças e atribuições de terceiros

Auditoria inicial de 2026-11-16, issue #177. A licença MIT cobre o código próprio, não concede direitos sobre dados, modelos, fontes ou outros componentes externos. Esta é uma análise técnica, não parecer jurídico nem liberação de distribuição pública.

## Inventário de dependências

A base `fce3976954cb717df6d2de6c5f38900f87ad1433` contém 337 resoluções npm distintas, dois locators de patch e sete workspaces (incluindo raiz). O lockfile não contém metadados de licença. `yarn licenses:inventory`, após `yarn install --immutable`, imprime registros LICENSE-ENTRY para todos os locators e LICENSE-SUMMARY. Cada linha identifica resolução, versão, dependência direta por workspace, candidatos ao runtime web/servidor e demais dependências, licença declarada nas cópias efetivamente instaladas e presença/hash dos avisos de topo. Os peers são classificados conservadoramente; a lista não é prova de inclusão no bundle. Pacotes de plataformas não instaladas, patches, ausência ou conflito de licença e avisos faltantes permanecem explícitos. Nome/versão correspondentes não demonstram identidade jurídica de todo arquivo transitivo.

O build web preserva o LICENSE MIT e os dois arquivos OFL byte a byte, copia avisos encontrados nos candidatos instalados ao runtime web e grava índice JSON. O aviso ODbL acompanha os dados. A página de licenças oferece o índice e o aviso dos mapas. Para distribuição do servidor e de outras plataformas é necessário repetir a revisão sobre o artefato efetivamente distribuído. Arquivos de aviso encontrados não significam que todas as obrigações foram satisfeitas.

## Política de distribuição

Antes de redistribuir publicamente uma versão compilada (incluindo hospedar a web, fornecer ZIP/container ou publicar binários), o mantenedor deve conferir as licenças e avisos de todos os ativos e componentes efetivamente redistribuídos. Não publicar artefato de produção com licença, origem ou obrigações de terceiros pendentes; substituir, remover ou obter confirmação autoritativa antes de liberar. O build de testes/local permanece disponível; a política não é um bloqueio automatizado de deploy e nenhum deploy foi feito. Não publicar os arquivos de modelo no Git. Não presumir que toda licença permissiva é satisfeita só com o campo SPDX.

Para adição/atualização de dependência ou ativo: fixar versão/origem e hash quando aplicável, inventariar runtime versus tooling, revisar textos LICENSE/NOTICE, licenças compostas, código incorporado e obrigações; registrar justificativa e avisos no artefato; repetir o inventário e os gates. Quando faltarem evidências, registrar responsável (maintainer) e impedir release público até resolução.

Pendências da auditoria: licenças/textos efetivos não conferidos de todos os componentes transitivos e plataformas, inspeção de pacote WASM e todos os conteúdos .task, proveniência/metadados dos subsets, avisos de artefatos do servidor e inspeção visual de screenshots. Não tratar o relatório local como atestado completo de conformidade.
